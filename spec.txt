**Organization:** TPT Solutions (`tpt-solutions`)
**Repository:** `tpt-electronics`
**Crate Prefix:** `tpt-elec-*`
**License Strategy:** Strict MIT-Only Chain

---

## 1. Executive Summary
As AI data centers and microchips get hotter, thermal management is the primary hardware bottleneck. Simulating heat dissipation across a microscopic PCB requires coupled electro-thermal FEM. Legacy tools (FloTHERM, Icepak, Celsius) are incredibly expensive proprietary suites tightly coupled to specific EDA vendors (Cadence, Siemens). Open-source multiphysics is usually GPL.

`tpt-electronics` provides a lightweight, MIT-licensed PCB thermal stress simulator that integrates directly into standard EDA workflows, helping hardware engineers prevent their boards from melting before they go to fabrication.

## 2. Substrate Leverage
*   **`tpt-fem`**: Steady-state and transient heat transfer FEM, micro-scale hexahedral meshing.
*   **`tpt-science`**: Electromagnetics, Joule heating (electrical resistance generating heat).
*   **`tpt-engineering`**: Anisotropic thermal conductivity (materials conducting heat differently in X/Y/Z axes, like FR4 fiberglass).

## 3. Crate Taxonomy & Data Models

### Core & Geometry
*   **`tpt-elec-core`**: PCB layer stackups, component bounding boxes, thermal vias.
*   **`tpt-elec-pcb`**: Parser for PCB layout files (Gerber RS-274X, ODB++, KiCad). Extracts copper trace routing and calculates effective thermal resistance.
*   **`tpt-elec-package`**: Semiconductor package thermal modeling (BGA, QFN, heat sinks, thermal pads).

### Thermal & Electro-Thermal
*   **`tpt-elec-thermal`**: Conduction, convection, and radiation heat transfer FEM. Handles anisotropic tensors for PCB substrates.
*   **`tpt-elec-joule`**: Electro-thermal coupling. Calculates current density through traces and vias, converting electrical resistance into volumetric heat generation.
*   **`tpt-elec-emc`**: Basic electromagnetic interference (EMI) shielding effectiveness and skin depth calculations for high-frequency traces.

## 4. Dependency Graph & MIT Chain
*   **Allowed:** `tpt-fem`, `tpt-science`, `tpt-engineering`, `gerber-rs` (MIT) or custom Gerber parsers, `tracespace` (MIT/Apache concepts).
*   **Banned:** `FloTHERM` (Proprietary), `Elmer FEM` (GPL), `OpenFOAM` (GPL).
*   **Strategy:** PCB thermal analysis relies heavily on hexahedral meshing and anisotropic material tensors. `tpt-fem` handles the tensors via `tpt-math-linalg-fixed`, and `tpt-elec-pcb` handles the geometric extraction. Keep the meshing strictly voxel/hex-based to avoid complex tetrahedral meshing libraries.

## 5. Verification & Validation (V&V) Strategy
*   **JEDEC Standards:** Validate against JEDEC JESD51 standards for semiconductor thermal testing (e.g., JESD51-12 for LED packages).
*   **IPC-2152:** Validate trace current-carrying capacity and temperature rise against IPC-2152 standards for printed board design.

## 6. Phased Delivery
1.  **Phase 1:** `tpt-elec-pcb` (PCB layer stackup and trace geometry parser from Gerber/KiCad).
2.  **Phase 2:** `tpt-elec-thermal` (Steady-state thermal conduction FEM with anisotropic materials).
3.  **Phase 3:** `tpt-elec-joule` (Joule heating electro-thermal coupling).
4.  **Phase 4:** `tpt-elec-package` (Transient thermal analysis for power cycling of BGA/QFN packages).

## 1. Open Source Declaration

`tpt-electronics` is a fully open-source, MIT-licensed multiphysics simulation engine for electronic systems. Every crate, every algorithm, every data model is freely available under MIT OR Apache-2.0.

### Why Fully Open Source?

The electronics simulation space is dominated by two extremes:

1. **Proprietary enterprise tools** (Ansys, Cadence, Siemens, Altium) costing $50k-$500k per seat, locked behind NDAs and vendor lock-in.
2. **GPL-contaminated open source** (NGSpice wrappers, OpenFOAM, GMSH, Elmer) that legally prevents commercial integration without infecting your codebase.

`tpt-electronics` eliminates both problems:

- **No cost barrier:** Any engineer, startup, or hobbyist can use it freely.
- **No license barrier:** Enterprises can integrate it into proprietary products without copyleft contamination.
- **No server barrier:** WASM compilation means simulations run entirely in the browser or locally — no cloud dependency, no data exfiltration.

## 2. Executive Vision

`tpt-electronics` is a pure-Rust, MIT-licensed multiphysics simulation engine for electronic systems. It solves the critical problems that kill hardware projects:

1. **Thermal runaway** — components overheating and failing
2. **Electromigration** — traces burning out from excessive current
3. **Signal integrity** — high-speed traces suffering EMI and losses
4. **Power delivery** — voltage droop and ground bounce
5. **EMC compliance** — failing regulatory certification
6. **Battery safety** — thermal runaway propagation in packs

The engine ingests standard EDA manufacturing formats (Gerber, ODB++, IPC-2581, KiCad), constructs voxel/hexahedral FEM meshes, and runs coupled electro-thermal-electromagnetic simulations entirely in Rust. Because it compiles to WebAssembly, it can run inside a browser-based EDA tool, a VS Code extension, or a CI pipeline — with zero server round-trips and zero GPL contamination.

### Why Rust for Electronics Simulation

| Requirement | Rust Advantage |
|---|---|
| Millions of voxel elements | Zero-cost abstractions, no GC pauses |
| Anisotropic thermal tensors | `tpt-math-linalg-fixed` fixed-size arrays |
| Real-time EDA feedback | WASM compilation for sub-second results |
| Enterprise deployment | MIT-only chain, no GPL audit risk |
| GPU acceleration | `wgpu` compute shaders for transient heat |
| Memory safety | No segfaults in long-running simulations |
| Concurrency | Fearless concurrency for parallel mesh processing |

#### `tpt-elec-joule`

Joule heating (electro-thermal coupling).

```rust
pub struct JouleHeatingSolver {
    thermal: ThermalSolver,
    electrical: ElectricalSolver,
}

impl JouleHeatingSolver {
    pub fn solve_coupled(
        &self,
        voltage_sources: Vec<VoltageSource>,
        iterations: u32,
    ) -> CoupledResult {
        // Iterative coupling:
        // 1. Solve electrical: [G]{V} = {I}
        // 2. Calculate Joule heating: Q = I²R per voxel
        // 3. Solve thermal: [K]{T} = {Q}
        // 4. Update resistivity: ρ(T) = ρ₀(1 + α·ΔT)
        // 5. Repeat until convergence
    }
}
```

```rust
                let vth = self.threshold_voltage(vbs);
                if vgs < vth {
                    0.0
                } else if vds < vgs - vth {
                    let kp = self.parameters.kp;
                    let w = self.parameters.w.as_meters();
                    let l = self.parameters.l.as_meters();
                    kp * (w / l) * ((vgs - vth) * vds - 0.5 * vds * vds)

                    0.5 * kp * (w / l) * (vgs - vth).powi(2) * (1.0 + lambda * vds)
                }
            }
            // ... other levels
        }
```

### License Traps to Avoid

| Domain | GPL Trap | MIT Solution |
|---|---|---|
| SPICE simulation | NGSpice (BSD), proprietary model libraries | Clean-room device models in Rust |
| Signal integrity | HyperLynx, SIwave (proprietary) | IPC-2141 equations, Touchstone parser |
| RF design | ADS, HFSS (proprietary) | Analytical models, Method of Moments |
| Power electronics | PLECS, SIMetrix (proprietary) | State-space averaging in Rust |
| EMC simulation | CST, HFSS (proprietary) | FDTD in Rust, analytical shielding |
| Battery modeling | PyBaMM (BSD), MATLAB toolboxes | Rust equivalent circuit models |
| Semiconductor | TCAD tools (Synopsys, Silvaco) | Drift-diffusion in `tpt-fem` |
| Mesh generation | GMSH (GPL), Netgen (LGPL) | Custom hex/voxel meshing |
| CFD | OpenFOAM (GPL) | Simplified convection models |

- ✅ Public roadmap and RFC process
- ✅ No paywalls on features
- ✅ No artificial limitations
- ✅ Full documentation and examples

## 13. Summary

`tpt-electronics` is a fully open-source, MIT-licensed, pure-Rust multiphysics simulation engine covering the complete electronics engineering lifecycle:

- **Thermal** — PCB thermal management, Joule heating, convection
- **Circuit** — SPICE simulation, device models, noise analysis
- **Signal Integrity** — High-speed traces, eye diagrams, PDN
- **RF / Microwave** — Matching networks, filters, antennas
- **Power** — Converters, magnetics, control loops
- **Semiconductor** — Device physics, compact models
- **EMC / EMI** — Emissions, immunity, shielding
- **Battery** — Cell models, BMS, thermal runaway
- **Manufacturing** — DFM, boundary scan, yield prediction

All crates maintain the strict MIT chain, leverage the TPT substrates (`tpt-math`, `tpt-engineering`, `tpt-science`, `tpt-fem`), and compile to WebAssembly for browser-based simulation.

No proprietary cores. No open-core bait. No GPL traps. Just open source.
